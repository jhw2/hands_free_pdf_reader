# Hands Free PDF Reader

입모양으로 PDF 페이지를 넘길 수 있는 브라우저 기반 뷰어입니다.

## 실행

1. `npm install`
2. `npm run dev`
3. 브라우저에서 `http://localhost:3000` 접속

## 사용 방법

1. 사이트에 접속하면 입으로 넘기기가 자동으로 시작됩니다. 카메라 접근을 허용합니다. 별도 보정은 필요하지 않습니다.
2. **PDF 악보 열기**로 PDF를 엽니다. **잠시 멈추기 / 다시 시작**으로 감지를 제어할 수 있으며, 다음 방문에는 다시 자동으로 시작합니다.
3. **다음 페이지:** 입을 설정한 시간(기본 0.5초) 동안 벌려 유지합니다. 상단 사용법의 넘김 시간 설정에서 시간을 바꿀 수 있으며 다음 방문에도 유지됩니다.
4. **이전 페이지:** 입을 짧게 벌렸다 닫고 바로 다시 벌립니다. 빠르게 두 번 해도 인식되도록 짧은 벌림(0.04초 이상)을 허용합니다. 첫 벌림은 설정한 다음 페이지 넘김 시간 미만으로 하고, 닫은 뒤 0.6초 안에 두 번째 벌림이 감지되어야 합니다.
5. 페이지 이동 후 입을 닫으면 다음 동작을 받을 수 있습니다. 연속 이동 방지를 위해 이동 간 1.2초 간격이 적용됩니다.

터치나 마우스로 PDF를 왼쪽으로 밀면 다음 페이지, 오른쪽으로 밀면 이전 페이지로 이동합니다.

입을 계속 벌리고 있어도 페이지는 한 번만 이동합니다. 화면의 이전·다음 버튼으로도 이동할 수 있습니다.

PDF를 연 뒤 `−`/`+` 버튼으로 100%~200%까지 확대할 수 있습니다. 악보 너비는 화면 안에 유지되며, 가로 전체 보기에서는 100%도 화면 너비에 맞춰 표시됩니다. 화면 아래에 더 볼 내용이 있으면 카메라가 잡은 중립 자세보다 고개를 아래로 숙여 악보를 아래로, 위로 들어 위로 스크롤할 수 있습니다. 중립 자세로 돌아오면 멈추며, 입 동작은 확대 여부와 관계없이 항상 페이지 이동에 사용됩니다.

## 사용법과 동작 연습

상단의 **사용법**에서 **다음 페이지 / 이전 페이지**를 선택하면 각 동작의 입 모양 애니메이션과 설명을 볼 수 있습니다. 다음은 벌린 채 유지하기, 이전은 짧게 벌렸다 닫고 다시 벌리기입니다. 설명과 반복 애니메이션을 먼저 확인한 뒤 **직접 해보기**를 누르면 실제 카메라로 연습하고 성공 여부를 확인할 수 있습니다. 설명을 읽을 때는 연습 피드백이 나타나지 않으며, 사용법을 열어둔 동안에는 실제 악보가 넘어가지 않습니다. 넘김 시간은 같은 사용법 화면의 **다음 페이지** 설명에서 바로 설정할 수 있습니다.

## 언어

같은 주소에서 한국어와 영어를 지원합니다. 처음 방문하면 브라우저 기본 언어가 한국어(`ko`, `ko-KR` 등)일 때 한국어, 그 외에는 영어로 표시합니다. 상단 언어 선택에서 직접 바꾸면 다음 방문에도 선택한 언어가 우선 적용됩니다. 브라우저 저장이 제한되어도 현재 화면의 언어를 바꿀 수 있습니다.

## 기능

- `pdf.js` 기반 PDF 렌더링
- `MediaPipe FaceMesh` 기반 입모양 감지
- PDF 및 마지막 읽은 페이지 저장
- 자동 저장 실패 시 메모리에 악보를 유지하고 **다시 저장** 지원
- PDF 표시 오류 시 **다시 시도**로 복구
- 전체 보기와 수동 페이지 이동

## 악보와 음악 함께 연습하기

`/score-sync`에서 PDF를 열고 하단 메뉴에 YouTube 링크를 연결합니다. 재생 버튼이나 악보의 마디를 누르면 메뉴가 접히고 악보를 넓게 볼 수 있습니다. 손잡이를 클릭하거나 위아래로 끌어 메뉴를 열고 닫을 수 있습니다.

**보관함**에는 PDF·YouTube 링크·BPM·박자·시작 시간을 곡별로 자동 저장합니다. **새 악보 추가**는 기존 곡을 덮어쓰지 않습니다. 보관함에서 곡을 바꾸면 이전 재생을 멈추고 저장된 설정을 불러옵니다. 기존에 저장된 한 곡도 처음 실행할 때 이전됩니다. 저장은 현재 브라우저의 IndexedDB에 한정되며, 영상 파일 자체는 저장하지 않습니다.

**싱크 조절** 아래의 **반복 기호 수정**은 기본으로 접혀 있습니다. 자동 인식한 도돌이표·세뇨·D.S.·D.C.·Fine·Coda·1·2번 엔딩을 확인하고 추가·수정·삭제한 뒤 **저장**하면 재생 경로에 적용됩니다. 수정값은 곡별로 보관하며 **자동 인식으로 되돌리기 → 저장**으로 복원할 수 있습니다. 마디 구분이 변경된 악보는 기존 수정값을 바로 적용하지 않고 재확인을 안내합니다.

## 검증

- `node --test tests/*.test.cjs`
- `npm run build`
- 보관함 검증: 별도의 테스트용 Chrome 프로필에 원격 디버깅을 켠 뒤 `node tests/score-library.browser.cjs http://127.0.0.1:9222 http://127.0.0.1:3000` 실행. 실제 IndexedDB에서 기존 곡 이전, 개별 설정, 저장 실패와 삭제를 확인하며 임시 테스트 DB만 사용합니다.

악보의 도돌이표와 1·2번 괄호 인식을 변경할 때는 Node 테스트와 함께 브라우저에서 같은 PDF의 전체 재생 순서와 반복 구간 전후의 마디 이동을 확인합니다. Node와 브라우저의 Canvas 픽셀 배치가 다를 수 있으므로 마디 수가 일치하는 것만으로 인식 성공을 판단하지 않습니다.

### YouTube 제목 검색

같은 입력창에 노래 제목을 입력하면 YouTube 검색 결과가 나오고, 영상을 선택하면 현재 악보에 연결·저장됩니다. URL 직접 연결도 지원합니다.
서버 환경 변수 `YOUTUBE_API_KEY`에 YouTube Data API v3를 활성화한 프로젝트의 API 키를 설정하세요 (`.env.local`, 배포 시 Vercel 환경 변수). `NEXT_PUBLIC_` 접두사는 사용하지 마세요. 키에는 YouTube Data API v3 API 제한을 적용하세요. 키가 없으면 검색 설정 안내가 표시되며 URL 연결은 계속 가능합니다.
검색 요청은 입력이 멈춘 후 700ms 뒤에 보내고 서버 응답은 5분간 캐시합니다. API 할당량과 임베드 제한은 YouTube 정책에 따릅니다.
